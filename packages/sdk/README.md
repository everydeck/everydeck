# @everydeck/sdk: TypeScript adapters (server: Node ≥ 22 / Deno; browser)

```bash
npm install @everydeck/sdk
```

Transport contract 1.1-r0 (`event-batch.schema.json`). No dependencies; only `fetch`, `setTimeout`, `AbortController`, `crypto.randomUUID`.

- `@everydeck/sdk` (`src/index.ts`, built `dist/index.js`): `createEverydeck({ endpoint, credential, releaseKey, manifestDigest })` → `signal`, `error`, `log`, `identify`, `heartbeat`, `flush`, `close`, `stats`. Bounded buffer (500), batches ≤ 50 events / 64 KiB, retry only on 429/5xx/timeout/network (same batch id), final rejections dropped and counted, overflow reported as a `gap` event. No background thread: in an Edge Function `await everydeck.flush()` before returning the response.
- `@everydeck/sdk/browser` (`src/browser.ts`, built `dist/browser.js`): `initEverydeckBrowser({...})` → `action(name, fn, { objectType, objectRef })`, the explicit action callback `ctx.fetch` (pass it to an action-scoped request/client; preserve the app authentication session), `breadcrumb`, `setSubject`, `reset` (sign-out), `flush`. Captures unhandled errors/rejections and, on requests using `ctx.fetch`, non-2xx / network / timeout as `error` with `http { method, route (path only), status, duration_ms }`, plus `x-everydeck-operation-id` / `x-everydeck-attempt-id` headers for server-side correlation. Browser data is a claim; nothing here proves a business result. Statuses that are an expected answer (for example 404 = not created yet) are declared per request `ctx.fetch(url, init, { expect: [404] })` or per action `{ expectStatus: [404] }`; they are recorded as a step with `fields.expected = true`, never as an error. A thrown error is the same failure as a reported request only when it is that object or carries the failed `Response` as `cause`, `context` or `response`; it is then recorded as the step `<action>.failed` (`error_class`, `propagated_request_failure`, `request_error_class`). Every other thrown error stays an `error` with its sanitized message and frames; if a request of the same attempt failed before, it carries `fields.after_request_failure = true` as a hint, not as a cause.
- Failed requests in the browser without an action (`@everydeck/sdk/browser`): through `fetch` and `XMLHttpRequest` (axios), to every host, like Sentry's httpClientIntegration. Requests to the app (the page's own host, `captureHosts`, the same site such as `api.<domain>`, Supabase API paths on any host) report network errors, 4xx (401 only while a person is signed in) and 5xx as `page.request_failed`. Any other host reports 5xx with its host (`http.host`, contract 1.5-r0); 4xx and network errors there are only counted as the step `page.request_counted`, so an ad blocker that blocks analytics is no case. Never a body, a query or a header.
- Console errors in the browser: `console.error` is reported as `browser.console_error` (like Sentry's captureConsoleIntegration for the level `error`), with the text scrubbed like error messages and the frames of a passed error; objects of the app are never sent (only `[object]`). The console prints as before; the same error at most every 30 seconds, at most 50 different ones per page; an error already reported as unhandled is not reported twice. Off with `captureConsole: false` (or `captureUnhandled: false`).
- `@everydeck/sdk/server` (also exported from `@everydeck/sdk`): server errors without a hand-written signal, one line per framework. Every unhandled exception while answering a request and every answer with status 500 to 599 becomes one `server.request_failed` event with method, route as a pattern, status, duration, error class, scrubbed message, frames and the run ids of a browser action (`x-everydeck-*` headers). Never a body, a query, a cookie or any other header; the app's answer is unchanged and exceptions are rethrown. 4xx is the app's answer and is not reported.
  - Express 4 and 5, after all routes and before your own error middleware: `everydeckExpress(app, everydeck)`
  - Next.js 15 or later, `instrumentation.ts`: `export const onRequestError = everydeckOnRequestError(everydeck)` (route handlers, pages, server actions, middleware)
  - Next.js route handler that answers 5xx itself: `export const POST = everydeckRoute(everydeck, handler)`; Pages Router API route: `export default everydeckApiRoute(everydeck, handler)`
  - Supabase / Deno Edge Function: `Deno.serve(everydeckServe(everydeck, handler))`
  Short-lived runtimes wait for the send on the error path only (at most 2 s).
- Deno / Supabase Edge Functions import the package as `npm:@everydeck/sdk@<version>` (see the examples below).


Version 0.1.1: browser actions no longer use ambient async context. Migrate `everydeck.action(name, async () => everydeck.fetch(...))` to `everydeck.action(name, async ctx => ctx.fetch(...))`; `everydeck.fetch` is unbound and `currentAction()` always returns null. Bind data-library requests explicitly; do not change a shared global client during concurrent actions. `ActionMeta` accepts `operationId` and `attemptId`; retry creates a new attempt and keeps the operation. User identity is captured at action creation.

Version 0.1.2: `ctx.fetch` takes an optional third argument `{ expect: number[] }`, `ActionMeta.expectStatus` declares expected statuses for a whole action, and an attempt reports at most one error (see above). Without a declaration every non-2xx inside an action is still a failed request.

Version 0.1.3: with everydeck disabled the SDK adds no headers to app requests. `correlate: (url) => boolean` in `initEverydeckBrowser` excludes targets whose CORS policy does not allow the `x-everydeck-*` headers (captured without correlation). `ctx.expecting([404])` returns a plain `fetch` with that expectation for data clients such as supabase-js.

Version 0.1.4: an attempt id alone no longer links a thrown error to an earlier failed request (0.1.2/0.1.3 downgraded any later throw to a step and lost its message and stack). Link by passing the failure on: rethrow it, or `throw new Error(message, { cause: response })`.

Outbox senders pass `eventId` (UUID) and `occurredAt` (ISO timestamp) in signal/error/log options. Preserve these across process restarts and lost acknowledgements. Invalid supplied IDs are dropped, never silently regenerated. `flush(timeout)` returns false for pending data or rejection during that call. Inspect acceptance/rejection counters before acknowledging a durable outbox; flushing is not a business-result proof. Timer, flush, close and keepalive share a sender. Buffer loss is reported even without a later app event. Hard process termination needs an external durable outbox.

## 0.1.5

- `releaseKey: 'auto'` (Node entry `@everydeck/sdk`) or `resolveReleaseKey()`: `EVERYDECK_RELEASE_KEY` (unless `auto`) → deployment commit from `GITHUB_SHA`/`VERCEL_GIT_COMMIT_SHA`/`RENDER_GIT_COMMIT`/`CF_PAGES_COMMIT_SHA`/`COMMIT_REF`/`SOURCE_VERSION`/`CI_COMMIT_SHA` as `git:<sha12>` → local git `git:<sha12>` or `git:<sha12>+dirty.<hash8>` (hash over `git diff HEAD` and non-ignored new files) → `unknown`. Same rule in the Python SDK (`release_key="auto"`, `resolve_release_key()`) and `everydeck-agent version`. Deno/Edge (`core.js`) has no git: pass the deployment commit explicitly.
- `probeId` (option of `createEverydeck`/`initEverydeckBrowser`): marks every batch of that client as part of a setup probe run. Only for verification scripts, never in the app's own client.

## 0.1.6

- Transport like Sentry/PostHog: batches are sent gzip-compressed wherever the runtime has `CompressionStream` (Node ≥ 18, Deno, modern browsers; `compress: false` turns it off), `Retry-After` on 429/503 is honoured (no attempt before it passes, not even from `flush()`), retries back off with full jitter (uniform in `[0, min(maxBackoffMs, 500 ms · 2^n)]`). `stats` gained `batches_compressed`, `bytes_raw`, `bytes_sent`, `retry_after_waits`. Helpers `fullJitterMs`, `parseRetryAfter`, `gzipText` are exported. The Python SDK (0.1.1) behaves the same.

## 0.1.7

- Signed bridge calls, like Stripe: everydeck signs every call to a read or app bridge (`X-Everydeck-Timestamp`, `X-Everydeck-Request-Id`, `X-Everydeck-Signature: v1=…[,v1=…]`; HMAC-SHA256 over method, path from `/everydeck/` with query, timestamp, request id and the SHA-256 of the body). `verifyEverydeckRequest({ method, url, headers, body }, { keys })` is the one line for the app's door (Web Crypto; Node, Deno, browsers): rejects calls older than 5 minutes and repeated request ids (`memorySeen` per process, `seen` for several instances). `createReadBridge` verifies by itself (`signatures: "required"` by default, `"optional"` only for everydeck instances that do not sign calls yet, `"off"`), reports `signed: true`. Key rotation: register the new key with everydeck, then switch the app; everydeck signs with both keys for 24 hours. `signEverydeckRequest` produces the same headers for the app's own tests. The Python SDK (0.1.2) behaves the same (`everydeck.verify`).

Version 0.1.8: every failed request to `captureHosts` (default: the page's own host) is reported without an action (network errors; 4xx, with 401 only while `setSubject` names a person; 5xx) as `page.request_failed` with the page (`trail`), the route pattern and the status, never with contents; the SDK wraps `globalThis.fetch` once for that (`captureBackground: false` switches it off, `uninstall()` removes the wrapper). `everydeck.fetch` captures the same way again; an update never switches capture off silently. Requests inside an action are reported by `ctx.fetch` exactly as before (no double report); everydeck's own sending is never captured. The generic read bridge serves `GET /everydeck/read/messages/{type}/{ref}` from `scope.conversations` when you pass `match: pgMatch(client, { schema })`.

## 0.3.0

- The read bridge is a ready-made route: `everydeckReadBridge({ endpoint, key, db })` from `@everydeck/sdk/read-bridge` (no `node:` module, runs in Deno / Supabase Edge Functions and Node). `db` is the connection the app already has (postgres.js, a pg `Pool`, or an object with `readOnly(fn)`); every query runs in its own read-only transaction, so the database refuses any write (SQLSTATE 25006). No read role, no views, no copied files.
- The read scope is no longer a file in the repository: the route fetches it from everydeck (`GET <endpoint>/v1/read-scope` with the bridge key) and uses it only when everydeck's signature (`EVERYDECK-SCOPE-V1`, HMAC-SHA256 with the bridge key) is valid; otherwise it reads nothing and answers 503.
- The rights it reports are checked: the role of the connection, `superuser`, `bypass_rls` (the role skips the app's row-level security and sees every row) and `read_only_transaction`.
- Supabase Edge Function (`supabase/functions/everydeck-read-bridge/index.ts`), environment `EVERYDECK_URL` and `EVERYDECK_READ_BRIDGE_TOKEN`; `SUPABASE_DB_URL` is provided by Supabase. The function keeps its JWT check: everydeck sends the app's public key (registered as `gateway_key`) as `apikey`:

```ts
import postgres from 'npm:postgres@3.4.5';
import { everydeckReadBridge } from 'npm:@everydeck/sdk@0.3.0/read-bridge';
const sql = postgres(Deno.env.get('SUPABASE_DB_URL')!, { prepare: false, max: 2, idle_timeout: 20 });
Deno.serve(everydeckReadBridge({ endpoint: Deno.env.get('EVERYDECK_URL') ?? '', key: Deno.env.get('EVERYDECK_READ_BRIDGE_TOKEN') ?? '', db: sql, prefix: '/everydeck-read-bridge' }).fetch);
```

## 0.5.8

- **A quiet read bridge sends almost nothing.** everydeck asks once per read (every 10 minutes) whether anything changed, like HTTP `ETag` / `If-None-Match` with `304 Not Modified`: the bridge answers `GET /everydeck/read/etags?limit=<page size>` with one fingerprint per type and for the people (the pages a full read would deliver now, folded in order, with their count), and everydeck fetches only the types whose fingerprint differs from its last full read. Before, every read sent every page through everydeck, even when nothing had changed. A page carries its own `etag` only when everydeck asks for it (`etag=1`), so an older everydeck sees exactly the pages and capabilities it knows; the capabilities are unchanged. The bridge still reads the rows to form the fingerprints (same queries as a full read, read-only); a type with more than 50,000 rows gets no fingerprint and is read in full as before, the types after it keep theirs; past 5 s for the whole request the rest is read in full. Deploy everydeck first, then redeploy the Edge Function with this version; with 0.5.7 and older everydeck reads every page as before.

## 0.5.7

- **A new person is in everydeck within seconds.** The read bridge answers `GET /everydeck/read/people/{subject_ref}` with exactly this person (the same fields and name rule as the list, 404 when the app does not know the identifier, also one its key column cannot hold) and names `people.fetch_one: true` in its capabilities. everydeck asks for a person right after an event names someone it does not know yet (a new sign-up), instead of waiting for the next read every 10 minutes, at most 20 asks per environment and minute. With 0.5.6 and older, everydeck reads the first pages of the people list instead. Nothing to change in the app; redeploy the Edge Function with this version.

## 0.5.6

- **A quiet read bridge asks everydeck less often.** One pull waits up to 50 s (before 25 s, like GitHub's runners; `PULL_WAIT_S`), and the Supabase Edge Function pulls 100 s per call (before 125 s): two long polls per call instead of five, the schedule still starts one every minute, so one call is always connected. A bridge with nothing to do asks about 120 times an hour instead of 300. Requests still arrive at once (everydeck wakes the waiting pull). An older everydeck caps the wait at 25 s itself, nothing else to change.

## 0.5.5

- **Signed out only with `reset()`** (like PostHog `reset()`). `setSubject(null)` now only says that nobody is known right now; it no longer forgets the person signed in on this device. Apps that start with no session and call `setSubject(null)` before Supabase restored the session (a reload) sent a sign-in on every reload; now a restored session of the same person is no sign-in. Call `everydeck.reset()` where the app signs the person out: the next person named is a sign-in again, also the same one. Without `reset()` a sign-out followed by a sign-in of the same person on the same device is not counted as a new sign-in; another person always is.
- **A declared write names its record and the new status.** `writes` entries as everydeck hands them out may carry `object` and `key` (object type and key column of the table) and `status` (the status column): an update or delete with the filter `?<key>=eq.<ref>` (as supabase-js sends `.eq('id', …)`) carries `object_type` and `object_ref` on every event of its run (a reference, like the outbox), and an update sends the new status as `fields.to_status` on `<flow>.finished`, only when it is a short code (`confirmed`, `completed`), never another value of the body. everydeck shows the run as one line in words ("set a booking to Confirmed (Luna, 30 Oct)"). `writes` with only flow, table and kind work as before. An older everydeck drops `to_status` (not an allowed field there), so update everydeck first.

## 0.5.4

- **Visits and sign-ins arrive by themselves** (like PostHog `$pageview` and `$identify`). The browser SDK sends one event `everydeck.sdk.page` for every change of the address (and every `screen()` of a native app) with the page only as its pattern from `screens` (`/jobs/:jobId`, never the address with an id or a query), the session of this page life and the person of `setSubject`. `setSubject` with a person who was not signed in on this device sends `everydeck.sdk.sign_in` once; a reload with the same person is no sign-in, `setSubject(null)` (signed out) forgets the person (since 0.5.5 only `reset()` does, see above; the only thing kept in the browser's storage, and only while someone is signed in). Page views go out in the normal batches; at most 500 per page life, the rest is reported as a gap (`sdk_page_views`). everydeck never counts them towards the month. Off with `capturePageViews: false`. Nothing to build into the app: `screens` and `setSubject` are already part of the setup. An older everydeck keeps these events out, so update everydeck first.

## 0.5.3

- **When a record was created.** The read bridge delivers `created_at` from the column the database sets when a record is created (`created` in the read scope, per object type and for people), so everydeck can show the app's past from before it was connected. A timestamp as Postgres writes it as text (`2026-10-25 23:59:16.774+00`, offset without minutes) is read too.

## 0.5.2

- **Schedules in plain SQL send their heartbeat through the outbox** (like Sentry Crons check-ins). `outbox/everydeck_outbox.sql` brings `everydeck_outbox.run_job('<job>', $job$ <command> $job$)` and `everydeck_outbox.job_heartbeat('<job>', 'ok' | 'error' | 'in_progress')`: a pg_cron job runs its command inside run_job, which writes the beat with its result into the outbox in the same transaction; the relay delivers it as the job heartbeat (`fields.job`, `fields.status`). No key in SQL. A failed command rolls back its writes and reports `error`; the schedule itself then ends without error (only the SQLSTATE goes to the log), because a failed schedule would roll back its beat too. Copy the new `everydeck_outbox.sql` unchanged as a new migration (idempotent; it adds the column `job_status`). The relay reads outboxes from before 0.5.2 as before. Update everydeck first: an older everydeck takes every job beat as a success.

## 0.5.1

- **Several refunds and failed attempts of one order.** `everydeck.payment('order_refunded', { orderId, refundId, … })` with the provider's id of this one refund (Stripe `re_…`) and `payment_failed` with `attemptId` (Stripe `ch_…`): two partial refunds of 20 and 30 on a payment of 100 count as 50, retries count each. The same refund delivered twice still counts once. Without these ids everything stays as before (one refund and one failure per order). `provider` (the name in money.providers of the app map, such as `stripe`) says which provider a payment came from. An older everydeck keeps the second refund out, so update everydeck first.
- **Image and audio calls are measured.** `wrapOpenAI` also measures `images.generate`, `images.edit`, `audio.transcriptions.create`, `audio.translations.create` and `audio.speech.create` (operation `image_generation`, `audio_transcription`, `audio_speech`; tokens where OpenAI reports them). everydeck's price list prices text tokens only: these calls show their cost as unknown unless you set a price of your own. `aiCall({ operation: 'image_generation', … })` for such a call the app measures itself. Update everydeck first.

## 0.5.0

- **The read bridge fetches its requests from everydeck (pull, outbound only, like a CI runner).** `everydeckReadBridge({ endpoint, key, db })` has `pull({ budgetMs, signal })`, `startPull()` for a server of its own and `pullHandler()` for a Supabase Edge Function: it fetches the next request with a long poll (`GET <endpoint>/v1/read-bridge/next`), answers it with the same signature check as before and sends the answer back (`POST <endpoint>/v1/read-bridge/reply/:id`). everydeck needs no address of the app and no key from it. On Supabase the schedule `bridge/everydeck_read_bridge_schedule.supabase.sql` starts the function every minute; each start fetches for about two minutes.
- **No key from the developer's machine to everydeck.** The outbox schedule needs only the relay URL; `everydeck_outbox_gateway_key` is optional. In a hosted project that the owner connected, everydeck deploys the relay and the read bridge itself, without the gateway's JWT check (each checks its own key, like the write door), so it needs no public key.
- **Server errors without a hand-written signal** (`@everydeck/sdk/server`): `everydeckExpress(app, everydeck)` for Express 4 and 5, `onRequestError = everydeckOnRequestError(everydeck)` for Next.js 15 or later, `everydeckRoute` and `everydeckApiRoute` for Next.js handlers that answer 5xx themselves, `Deno.serve(everydeckServe(everydeck, handler))` for Supabase and Deno Edge Functions. Unhandled exceptions and answers with status 500 to 599 become `server.request_failed` with the route pattern of the framework (`http.pattern`, kept by everydeck as it is); never a body, a query, a cookie or another header.
- **Failed requests in the browser through `XMLHttpRequest`** (axios) as well as `fetch`, and to every host without `captureHosts`: the app's hosts (own host, same site, Supabase API paths) as before; any other host reports 5xx with its host (`http.host`) and only counts 4xx and network errors (`page.request_counted`).
- **Console errors**: `console.error` becomes `browser.console_error` (scrubbed text, frames of a passed error, never objects of the app); `captureConsole: false` turns it off.
- **Scrubbing stays cheap**: secrets, bearer tokens and e-mail addresses are removed in linear time, and the SDK scrubs at most 8 192 characters of a text (like Sentry's limit for an exception's value); a longer text is cut first and ends with `…`, a stretch cut in half at the limit is left out. An app with a huge error message never stalls in the SDK.
- **Sending time** in the header `x-everydeck-sent-at`, so everydeck can correct a device clock that is off by an hour or more (like Sentry's `sent_at`); the body of a retry stays the same.
- **Where a person came from** (browser): on the first visit the SDK keeps the UTM values of the address (`utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`) and the domain of the referring page (never its path or query, nothing from the same site) in `localStorage`; later visits do not overwrite it. Once the person is known (`setSubject`), one step `everydeck.sdk.origin` carries these values to everydeck, once per person and device, like PostHog's `$initial_utm_*` and `$initial_referring_domain`. Opened directly or inside the native shell without a referring page: nothing is sent. `captureOrigin: false` turns it off.
- **Settings read again while running**: `everydeckFromSupabase` reads `public.everydeck_server_config()` again every 5 minutes (`refreshSeconds`, 0 = only at start), the way PostHog polls its flag definitions. A new approval in everydeck (manifest digest) or a new server key reaches a long-running server without a restart; batches built after the read carry the new values (`reconfigure()` on the client does the same by hand). A failed read keeps the last settings (one warning that names the function, never a value). A client switched off at start because the function was not there yet switches itself on once the values arrive. Environment variables stay fixed.
- **Source maps for errors in the browser code**, the way Sentry does it with debug ids. With Vite: `import { everydeckSourceMaps } from '@everydeck/sdk/vite'` and `plugins: [react(), everydeckSourceMaps({ url: 'https://<your everydeck>' })]`. In `vite build` it turns on source maps without the `sourceMappingURL` comment, gives every built file a debug id (a short snippet at the start of the first line, so no line moves, and `//# debugId=` at the end), uploads the maps with the key that can only upload source maps (`EVERYDECK_SOURCEMAPS_KEY`, in the build settings of the hosting or the app's git-ignored `.env.local`; never under a public name such as `VITE_` or `NEXT_PUBLIC_`, then nothing is uploaded) and removes them from the output folder, also without a key or when the upload failed: the maps are never public, and the build never fails because of everydeck. Before a map leaves the machine, the code of libraries (`node_modules`) is dropped from it and every other line is scrubbed like error messages. Any other bundler: `npx everydeck-sourcemaps inject <output folder>` and `npx everydeck-sourcemaps upload <output folder> --url https://<your everydeck>` after the build (the same code, `@everydeck/sdk/sourcemaps`). The browser SDK then sends the column and the debug id of each frame in such a file, and everydeck shows the source file, line, function and code lines of the error. Errors from a build whose maps were not uploaded stay as before.
- **Load times of every page** (browser, on by default): the SDK measures LCP, INP and CLS (Core Web Vitals) and FCP and TTFB with Google's `web-vitals` 6.2.3 (Apache-2.0, shipped inside the SDK, see `THIRD-PARTY-NOTICES.md`; no dependency) and sends one event `everydeck.web.vitals` per page view when the page is hidden, with the page only as its pattern (`screens`), never a person or an address. Route changes of a single-page app count as page views of their own where the browser reports soft navigations (Chromium 151+). everydeck never counts these events towards the month and keeps only daily values per page. Native apps (React Native, Expo, Capacitor) measure nothing; `captureVitals: false` turns it off. An older everydeck rejects these events from a browser key, so update everydeck first.
- Transport contract 1.6-r0 (`http.host` since 1.5-r0; since 1.6-r0 a browser frame in a file with a debug id carries its column, the full path of the file without query and the `debug_id`). everydeck accepts it from this version on; an older everydeck rejects these batches, so update everydeck first.
- **Counts per type** for everydeck's data loss watch: the read bridge answers `GET /everydeck/read/counts` (rows per table of the read scope, `count(*)` in a read-only transaction, like the row count of Elementary's volume test) and names `count: true` per type in its capabilities; `pgCount(client)` for a bridge of your own. everydeck then checks a large table without waiting for a full read. An older everydeck does not know `count` in the capabilities, so update everydeck first.
- **A date column is the same calendar day in every time zone of the app server**: the read bridge sends a `date` (and `date[]`) as midnight UTC of that day (`2026-10-19T00:00:00.000Z`) with `pg` as well; before, node-pg built a Date at midnight in the server's local time and a server east of UTC sent the day before (Bali: `2026-10-18T16:00:00.000Z`). Only the bridge's own queries read `date` this way (node-pg `types` per query, never a global parser): the app's own code still gets a Date, every other type keeps the app's parsers. postgres.js and the Supabase bridge already sent this form; timestamps (`timestamptz`, `timestamp`) are unchanged.

- **Payments** (server only): `everydeck.payment(event, details)` where the app itself talks to its payment provider, in the code that opens a checkout and in the webhook it receives. Five events named after the Segment e-commerce spec and Stripe: `checkout_started` (`everydeck.checkout.started`), `order_completed` (`everydeck.order.completed`), `payment_failed` (`everydeck.payment.failed`), `order_refunded` (`everydeck.order.refunded`), `checkout_abandoned` (`everydeck.checkout.abandoned`). Only `total` (in the main unit of the currency, so 49.00 for 49 dollars; divide Stripe's cents by 100, except for zero decimal currencies such as JPY or IDR), `currency` (ISO 4217), `product`, `quantity`, the provider's `orderId` and `checkoutId` and a short `reason` for a failure (for example Stripe's `failure_code`), plus `subjectRef`, `accountRef`, `objectType`, `objectRef`. `orderId` (or `checkoutId` for a checkout) is required; the same id counts once per event, so a webhook delivered twice is safe. When the webhook stores the purchase as a row of a purchases table of the app map, pass that row's id as `orderId` (several rows for one payment: the first row's id and `quantity` the number of rows), so everydeck counts the purchase once. Never card data: an event with a value that looks like a card number (13 to 19 digits with a valid Luhn checksum) is not sent. No key of the provider ever goes to everydeck. An older everydeck does not know these events, so update everydeck first.
- **AI calls** (server only): `const openai = everydeck.wrapOpenAI(new OpenAI())` and `everydeck.wrapAnthropic(new Anthropic())` return the same client (it stays an `instanceof OpenAI`), like PostHog's `@posthog/ai` and Langfuse's `observeOpenAI`. Each call of `chat.completions.create`, `responses.create`, `embeddings.create` or `messages.create`, with or without `stream`, sends one event `everydeck.ai.generation` (PostHog's `$ai_generation`) with field names after the OpenTelemetry GenAI conventions: `gen_ai.provider.name`, `gen_ai.operation.name`, `gen_ai.request.model`, `gen_ai.response.model`, `gen_ai.usage.input_tokens` (counting cached tokens), `gen_ai.usage.output_tokens`, `gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_write.input_tokens`, `gen_ai.client.inference.duration` (seconds), `error.type` for a failed call (the error's class, never its message), and `everydeck.flow`. **Never the prompt, the answer, a system text or a key**: the wrapper does not read them. Name the flow, the person and the organization at the wrapper (`wrapOpenAI(client, { flow: 'cv_analysis', subjectRef, accountRef })`) or around the work (`everydeck.aiContext({ flow, subjectRef, accountRef }, () => …)`; the calls inside belong to one run). For a chat stream the wrapper asks OpenAI for the usage chunk (`stream_options.include_usage`) and does not pass that extra chunk to the app. `everydeck.aiCall({ provider, requestModel, inputTokens, outputTokens, … })` sends a call the app measured itself. everydeck prices the tokens with its own price list; the app sends no money and no key of the provider. An older everydeck does not know this event, so update everydeck first.

## 0.4.4

- **Settings of a server of its own from the Supabase project.** `everydeckFromSupabase(supabaseAdmin, { instanceId: 'api' })` reads endpoint, server key and manifest digest once from `public.everydeck_server_config()` through the server's Supabase client created with the service key, so nothing has to be copied into the hosting dashboard (Render, Railway, Fly, Vercel). `serverConfigFromSupabase(client)` returns the three values. When `EVERYDECK_ENDPOINT`, `EVERYDECK_SERVER_KEY` and `EVERYDECK_MANIFEST_DIGEST` are all set, they win. If the call fails, the client is switched off with a warning that names the function, never a value. Release key `auto` (the commit the host sets).
- **`outbox/everydeck_server_config.supabase.sql`**: the function, `SECURITY DEFINER` with an empty `search_path`, reading three Vault secrets (`everydeck_endpoint`, `everydeck_ingest_key`, `everydeck_manifest_digest`). Supabase grants `EXECUTE` on new functions in `public` to `anon` and `authenticated` by default privileges; the file revokes it from `PUBLIC`, `anon` and `authenticated` and grants it to `service_role` only.

## 0.4.0

- **Outbox from the package** (`@everydeck/sdk/outbox`): `relayOnce`, `createRelayHandler` for the scheduled Supabase function, and `npx everydeck-outbox-relay` for plain PostgreSQL. Migration, trigger template, schedule and README ship under `node_modules/@everydeck/sdk/outbox/`; nothing is downloaded.
- **`supabaseDbUrl()`** (`/outbox` and `/read-bridge`): `SUPABASE_DB_URL`, and in the local stack (`supabase start`) the name `db.supabase.internal` instead of the container name `supabase_db_<project>`, which Deno's resolver refuses. Both Supabase functions use `postgres(supabaseDbUrl(), …)`, so the bridge and the relay run in the local stack itself, never as a process of an agent session.
- **Browser writes as runs** (`initEverydeckBrowser({ …, writes: [{ flow, table, kind }] })`, the flows of the app map whose `result.write` is a table): a request to Supabase's `/rest/v1/<table>` with that kind (POST = insert, POST with `Prefer: resolution=…` or PUT = upsert, PATCH = update, DELETE = delete) becomes one run of the flow without an action: `<flow>.started` when it is sent, `<flow>.finished` on 2xx, `<flow>.request_failed` with status, PostgREST code and message otherwise (never the request body). The request carries `x-everydeck-operation-id` and `x-everydeck-platform`; the outbox trigger takes both from PostgREST's request headers, so start, result and failure are one run with its platform. Initialize the SDK in its own module imported **first** in the app's entry: supabase-js and similar clients keep the `fetch` they find when they are created.
